# URL Shortener

A production-oriented URL shortener written in Go. It accepts a long URL, returns a short, deterministic key, and redirects clients on lookup. Each create and redirect is logged for analytics, and unused URLs are eligible for cleanup based on a configurable threshold.

The codebase is also a worked example of the patterns you actually need to take a Go HTTP service to production: layered architecture with no import cycles, circuit-broken DB pools with replica fallback, distributed rate limiting, single-leader background work, full observability (traces + metrics + structured logs + pprof), graceful shutdown with the right ordering, and a distroless multistage container image. The [Production checklist](#production-checklist) below maps every one of those concerns to the file that implements it.

## Architecture: main to repo

A walking tour of how a request and the process lifecycle flow through the code. Each step is the next thing `main.main()` does, or the next layer a request crosses. Code snippets are excerpts — links go to the full file.

### Step 1: process entry

[`cmd/api/main.go`](cmd/api/main.go) — the whole composition root lives in one `main()` function. No package-level state, no init magic. The order is deliberate: each line stands up something the next line needs.

```go
func main() {
    cfg, err := config.LoadConfig()                  // 2. config first — drives everything else
    logger.Init(cfg.LogLevel)                        // 3. then logger — slog default for the rest
    runtime.SetBlockProfileRate(1)                   //    pprof block/mutex sampling on
    runtime.SetMutexProfileFraction(1)

    rootCtx, stop := signal.NotifyContext(           //    SIGINT/SIGTERM → cancels rootCtx
        context.Background(), syscall.SIGINT, syscall.SIGTERM)
    defer stop()

    tracerShutdown, _ := observability.InitTracing(rootCtx, ...)   // 4. tracer before any client
    metricsReg, appMetrics := observability.NewRegistry()          // 5. metrics registry + bundle

    router, primaryPool, closeRouter, _ := database.NewRouter(...) // 6. DB router (breakers inside)
    defer closeRouter()
    redisClient, _ := redisclient.NewClient(rootCtx, cfg.RedisURL) // 7. Redis (with redisotel hook)
    defer func() { _ = redisClient.Close() }()

    svcs, _ := service.New(service.Deps{                           // 8. service graph
        Router: router, Redis: redisClient, Config: cfg})

    cleanupLocker := leader.New(primaryPool)                       // 9. leader gate (advisory locks)
    cleanupCron := cron.NewCleanupCron(svcs.Cleanup, cfg, cleanupLocker)
    go cleanupCron.Start(rootCtx)                                  // 10. background cleanup

    debugSrv := /* :PprofPort, hosts /debug/pprof + /metrics */    // 11. debug server (private)
    srv := /* :ServerPort, hosts /shorten /:key /liveness /readiness */  // 12. API server

    // ... blocks until rootCtx done or srv errors ...
    /* graceful shutdown: drain HTTP → flush tracer → stop debug → deferred closes */
}
```

Everything below is what each numbered step does in detail.

### Step 4: tracing init

[`internal/platform/observability/tracing.go`](internal/platform/observability/tracing.go) — the whole point of this package is that **tracing is optional but always wired**. If `OtelExporterEndpoint` is empty, a no-op `TracerProvider` is installed — every later `otel.Tracer(...)` call still works, just becomes a near-zero-cost call. That keeps `otelgin` / `otelpgx` / `redisotel` always-on without forcing every dev environment to run a collector.

```go
func InitTracing(ctx context.Context, cfg TracingConfig) (ShutdownFunc, error) {
    otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(
        propagation.TraceContext{}, propagation.Baggage{},        // W3C, always installed
    ))
    if cfg.ExporterEndpoint == "" {
        otel.SetTracerProvider(noop.NewTracerProvider())
        return func(context.Context) error { return nil }, nil
    }
    exporter, err := otlptracehttp.New(ctx, otlptracehttp.WithEndpointURL(cfg.ExporterEndpoint))
    // ... build resource (service.name, version) and TracerProvider ...
    tp := sdktrace.NewTracerProvider(
        sdktrace.WithBatcher(exporter, sdktrace.WithBatchTimeout(5*time.Second)),
        sdktrace.WithSampler(sdktrace.ParentBased(sdktrace.TraceIDRatioBased(cfg.SampleRatio))),
    )
    otel.SetTracerProvider(tp)
    return tp.Shutdown, nil    // ShutdownFunc flushes BSP queue at process exit
}
```

The returned `ShutdownFunc` is what step "graceful shutdown" calls to drain pending spans.

### Step 5: metrics registry

[`internal/platform/observability/metrics.go`](internal/platform/observability/metrics.go) — a custom `prometheus.Registry` (not the global default) holds Go-runtime + process collectors plus the `AppMetrics` bundle. The bundle is what the rate-limit middleware and HTTP RED middleware write to.

```go
func NewRegistry() (*prometheus.Registry, *AppMetrics) {
    reg := prometheus.NewRegistry()
    reg.MustRegister(collectors.NewGoCollector(), collectors.NewProcessCollector(...))
    m := &AppMetrics{
        HTTPRequestsTotal:   prometheus.NewCounterVec(..., []string{"method", "route", "status"}),
        HTTPRequestDuration: prometheus.NewHistogramVec(..., []string{"method", "route", "status"}),
        RateLimitDecisions:  prometheus.NewCounterVec(..., []string{"decision"}),
    }
    reg.MustRegister(m.HTTPRequestsTotal, m.HTTPRequestDuration, m.RateLimitDecisions)
    return reg, m
}
```

`route` is always the Gin route template (`/:key`, `/shorten`) — never a raw URL — so cardinality stays bounded.

### Step 6: database router with circuit breaker

[`internal/platform/databse/`](internal/platform/databse/) — `NewRouter` builds either one or two `pgxpool.Pool`s (primary + optional replica) and wraps each in a `breakerDB`. Reads prefer the replica when its breaker is closed, fall back to primary otherwise. Writes are always primary.

```go
// pool.go — every pool gets the otelpgx tracer attached
config.ConnConfig.Tracer = otelpgx.NewTracer()

// router.go — Reader picks replica unless its breaker is open
func (r *poolRouter) Reader() repository.DBTX {
    if r.replica != nil && r.replica.cb.State() != gobreaker.StateOpen {
        return r.replica
    }
    return r.primary
}
```

The breaker itself is the interesting part. Every `Exec` / `Query` / `QueryRow` flows through `breakerDB.Execute`, which classifies the resulting error to decide whether it counts as a failure:

```go
// breaker.go — class-based SQLSTATE classification
func shouldCount(err error) bool {
    if err == nil { return false }
    if errors.Is(err, repository.ErrNotFound) { return false }   // not an infra failure
    if errors.Is(err, context.Canceled) { return false }         // client gave up
    if errors.Is(err, context.DeadlineExceeded) { return true }  // we timed out the DB

    var pgErr *pgconn.PgError
    if errors.As(err, &pgErr) {
        switch pgErr.Code[:2] {
        case "23", "42": return false                            // constraint / syntax — caller's fault
        case "53", "57", "58", "08", "XX": return true           // resource / connection / system — count
        }
    }
    return true                                                  // unknown — assume infra
}
```

Trip conditions: `ConsecutiveFailures >= 5` **or** error rate > 50% over 60s with at least 20 requests; half-open after 30s with a single probe. When open, calls return `repository.ErrCircuitOpen` synchronously without hitting the DB.

### Step 8: service wiring

[`internal/service/service.go`](internal/service/service.go) — `Deps` lists the infrastructure the service layer needs; `Services` is the typed aggregate of every business service. `service.New(deps)` builds the graph, including the rate limiter (only if Redis was wired):

```go
type Deps struct {
    Router repository.Router    // interface, not *pgxpool.Pool — see "Breaking the cycle"
    Redis  *redis.Client
    Config *config.Config
}
type Services struct {
    URL         URLService
    Cleanup     CleanupService
    RateLimiter RateLimiter
}
func New(d Deps) (*Services, error) {
    s := &Services{
        URL:     NewURLService(repository.NewURLRepository(d.Router), repository.NewRequestRepository(d.Router)),
        Cleanup: NewCleanupService(repository.NewURLRepository(d.Router), d.Config),
    }
    if d.Redis != nil {
        s.RateLimiter = NewRedisRateLimiter(d.Redis, d.Config.RateLimitPerMinute, d.Config.RateLimitWindow, d.Config.RedisOpTimeout)
    }
    return s, nil
}
```

### Steps 9 and 10: leader gate and cleanup cron

[`internal/platform/leader/locker.go`](internal/platform/leader/locker.go) is the single-leader primitive. `Run` acquires a session-scoped Postgres advisory lock keyed by an `int64`; if someone else already holds it, `Run` is a silent no-op. The lock auto-releases when the connection closes — no stuck-leader scenario even on `kill -9`.

```go
func (l *Locker) Run(ctx context.Context, key int64, fn func(context.Context) error) error {
    conn, _ := l.pool.Acquire(ctx); defer conn.Release()
    var got bool
    _ = conn.QueryRow(ctx, "SELECT pg_try_advisory_lock($1)", key).Scan(&got)
    if !got { return nil }                                       // someone else is the leader this tick
    defer conn.Exec(context.Background(), "SELECT pg_advisory_unlock($1)", key)
    return fn(ctx)
}
```

[`internal/cron/cleanup_cron.go`](internal/cron/cleanup_cron.go) is the user of the gate. The ticker fires on every replica; only one wins the lock and actually deletes:

```go
const cleanupLockKey = int64(0xC1EA_F00D_C0DE)   // pick once, never change

for {
    select {
    case <-ticker.C:
        if err := c.locker.Run(ctx, cleanupLockKey, c.svc.RunCleanup); err != nil { ... }
    case <-ctx.Done():
        return
    }
}
```

### Step 12: HTTP router and middleware chain

[`internal/api/router.go`](internal/api/router.go) — order matters. `otelgin` runs first so its span wraps everything (rate-limit work shows up in the trace). HTTP metrics next, so its histogram includes the limiter check. `ContextProvider` injects the client IP for the limiter. `RateLimit` consults Redis last — it can short-circuit with a 429 before we ever hit a handler.

```go
r.Use(otelgin.Middleware(d.ServiceName))         // 1. one trace per request
r.Use(middleware.HTTPMetrics(d.Metrics))         // 2. RED counters/histogram
r.Use(middleware.ContextProvider())              // 3. ip → request context
r.Use(middleware.RateLimit(d.RateLimiter, rateLimitSkipPrefixes, d.Metrics))  // 4. quota check
```

The rate-limit middleware itself is short — it pulls the IP out of the context that step 3 just put there, calls the limiter, fails open on errors, and abort+429s on deny:

```go
// internal/api/middleware/ratelimit.go (excerpt)
ip := contextutil.GetClientIP(c.Request.Context())
allowed, remaining, retryAfter, err := limiter.Allow(ctx, ip)
if err != nil {                                      // fail-open: Redis blip ≠ API outage
    slog.WarnContext(ctx, "rate limiter unavailable, allowing request", ...)
    record("error"); c.Next(); return
}
c.Header("X-RateLimit-Remaining", strconv.Itoa(remaining))
if !allowed {
    c.Header("Retry-After", strconv.Itoa(int(math.Ceil(retryAfter.Seconds()))))
    response.Error(c, http.StatusTooManyRequests, response.CodeRateLimited, "rate limit exceeded")
    record("deny"); c.Abort(); return
}
record("allow"); c.Next()
```

### Step 13: handlers

[`internal/api/handlers/url_handler.go`](internal/api/handlers/url_handler.go) — handlers are thin. They derive a per-endpoint timeout, validate input, call the service, and translate errors into the response envelope. Each error path logs with `slog.*Context` so the request's traceparent flows into the log line.

```go
const createTimeout = 10 * time.Second

func (h *URLHandler) Create(c *gin.Context) {
    ctx, cancel := context.WithTimeout(c.Request.Context(), createTimeout)
    defer cancel()
    var input ShortenRequest
    if err := c.ShouldBindJSON(&input); err != nil {
        response.Error(c, http.StatusBadRequest, response.CodeInvalidInput, err.Error()); return
    }
    res, err := h.Service.ShortenURL(ctx, input.URL, c.Request.UserAgent())
    if err != nil {
        if handleContextErr(c, err) { return }                   // 504 on timeout, 499 on cancel
        response.Error(c, http.StatusInternalServerError, response.CodeInternal, "failed to create short url"); return
    }
    response.OK(c, http.StatusCreated, res)
}
```

The handler timeout (10s) is **shorter than** the global `dbCallTimeout` (5s) × number of DB calls plus headroom — so the handler is always the binding deadline, never the DB. That keeps client-perceived latency predictable.

### Step 14: response envelope

[`internal/api/response/response.go`](internal/api/response/response.go) — every success and every failure goes through one of two helpers, so every JSON body has the same shape and every error has a stable code that clients can match on.

```go
type Envelope struct {
    Success bool        `json:"success"`
    Data    interface{} `json:"data,omitempty"`
    Error   *APIError   `json:"error,omitempty"`
}
const (
    CodeInvalidInput = "invalid_input"
    CodeNotFound     = "not_found"
    CodeUnavailable  = "unavailable"
    CodeInternal     = "internal_error"
    CodeTimeout      = "timeout"
    CodeRateLimited  = "rate_limited"
)
func OK(c *gin.Context, status int, data interface{})           { c.JSON(status, Envelope{Success: true, Data: data}) }
func Error(c *gin.Context, status int, code, message string)    { c.JSON(status, Envelope{Success: false, Error: &APIError{code, message}}) }
```

### Step 16: services use repos through interfaces

[`internal/service/url_service_impl.go`](internal/service/url_service_impl.go) — the service depends on `repository.URLRepository` (an interface), not on a concrete struct. The collision-retry loop demonstrates the pattern — the service owns the *policy*, the repo owns the *SQL*.

```go
func (s *urlService) ShortenURL(ctx context.Context, originalURL, userAgent string) (*model.URL, error) {
    shortKey := shortKeyFromURL(originalURL)
    for attempt := 0; attempt <= maxCollisionRetries; attempt++ {
        existing, err := s.urlRepo.GetByShortKey(ctx, shortKey)
        if err == nil {
            if existing.URL == originalURL { /* same URL re-shortened — return existing */ }
            shortKey = shortKeyFromURL(fmt.Sprintf("%s:%d", originalURL, attempt+1))   // salt + retry
            continue
        }
        if errors.Is(err, repository.ErrNotFound) { break }
        return nil, fmt.Errorf("lookup short key: %w", err)
    }
    /* Create + fire-and-forget log on a detached, bounded ctx — the request ctx is
       already done by the time the goroutine runs the "log this hit" call */
}
```

Note the **fire-and-forget pattern in `Redirect`**: the response is sent (request ctx is now canceled), but `UpdateLastUsed` runs on a fresh `context.WithTimeout(context.Background(), 2s)` so the goroutine still has a deadline.

### Step 17: repository

[`internal/repository/`](internal/repository/) — repos are SQL with a typed signature. They take a `context.Context` first, return models, and never know what kind of DB-like thing they're talking to:

```go
// db.go — the seam
type DBTX interface {
    Exec(ctx context.Context, sql string, args ...any) (pgconn.CommandTag, error)
    Query(ctx context.Context, sql string, args ...any) (pgx.Rows, error)
    QueryRow(ctx context.Context, sql string, args ...any) pgx.Row
}
// repo.go — every DB call has a hard cap
const dbCallTimeout = 5 * time.Second
```

`*pgxpool.Pool`, `pgx.Tx`, and our `breakerDB` all satisfy `DBTX`. That's why the repository tests can run inside a transaction that auto-rolls back, and why the production code goes through the breaker — same interface, different implementations.

### Step 18: graceful shutdown

Back to [`cmd/api/main.go`](cmd/api/main.go) — when `rootCtx.Done()` fires (SIGINT/SIGTERM), the order is exactly the inverse of startup:

```go
shutdownCtx, cancel := context.WithTimeout(context.Background(), shutdownTimeout)  // detached, bounded
defer cancel()

srv.Shutdown(shutdownCtx)        // 1. drain in-flight HTTP requests (their handlers complete spans)
tracerShutdown(shutdownCtx)      // 2. flush BSP queue — last-request spans get exported
debugSrv.Shutdown(shutdownCtx)   // 3. close /debug/pprof and /metrics
// 4. defers run in LIFO order on return: redisClient.Close() → closeRouter() (DB)
```

The shutdown context is **detached from `rootCtx`** so a second `Ctrl+C` doesn't immediately abort the drain — it just cancels the second wait.

## Topics in depth

### Breaking the dependency cycle

Go forbids import cycles. The natural shape — `service → repository → database → service` (because the breaker logs metrics? validates auth? takes config?) — is the trap. The cure is to **define interfaces where they're consumed, not where they're implemented**.

- `repository.URLRepository` is declared in `internal/repository/url_repo.go`. The implementation `urlRepository` (in the same package) satisfies it. The service depends on the interface.
- `repository.Router` is declared in `internal/repository/` too — but it's *implemented* in `internal/platform/databse/`. The database package imports `repository` to satisfy the interface; nothing in `repository` imports `database`.
- `repository.DBTX` ([db.go](internal/repository/db.go)) is the same trick at a finer grain — the repos accept anything that quacks like a pgx pool, so tests can pass a `pgx.Tx` and prod passes a `breakerDB`.

In practice: every direction of import flows from outer rings to inner rings — `cmd → api → service → repository → model`. `platform/*` is leaf-level infrastructure that *implements* interfaces from `repository`, never the other way round.

### Context discipline

Three layers, three context concerns:

1. **HTTP request context** lives for the request. Gin gives you `c.Request.Context()`; we wrap it with `context.WithTimeout(_, createTimeout)` per handler so the handler is the binding deadline.
2. **Per-DB-call timeout** ([repo.go](internal/repository/repo.go)) caps every Exec/Query at `dbCallTimeout = 5s`. `context.WithTimeout` only *shortens* a deadline, so when a handler passes a tighter ctx, the handler still wins.
3. **Detached background work** uses `context.WithTimeout(context.Background(), ...)` — like the fire-and-forget `UpdateLastUsed` after a redirect. We deliberately don't inherit the request ctx because it's already canceled by the time the goroutine runs.

Context **values** go through typed helpers ([contextUtil/context.go](internal/contextUtil/context.go)) — never raw strings. The two values that flow today are the client IP (set in middleware, read by the rate limiter) and a circuit-open flag.

### Logging, traces, and metrics: how they relate

- **slog** answers "what happened" — structured key/value records to stdout. Every `slog.*Context(ctx, ...)` call carries the request context, which is how the trace ID can be correlated by downstream log shippers.
- **OpenTelemetry traces** answer "where was time spent" — one span per inbound HTTP, child spans per DB query and Redis command, plumbed automatically by `otelgin` / `otelpgx` / `redisotel`.
- **Prometheus metrics** answer "is anything trending the wrong way" — RED for HTTP, decisions for the rate limiter, plus Go runtime collectors. Bounded cardinality is the discipline (route templates, never raw URLs).

The graceful-shutdown order respects all three: HTTP drain finishes spans, then `tracerShutdown` flushes them; the debug server (which serves `/metrics`) is the last thing to close so a final scrape can succeed if it's already in-flight.

## Description

- Deterministic short keys derived from a SHA-256 hash of the URL, encoded in base62 to 11 characters.
- Hash-collision handling via salted re-hash up to 5 retries.
- Persistent storage in PostgreSQL via `pgx` connection pooling, with optional read-replica routing and per-pool circuit breakers.
- **Distributed rate limiter** backed by Redis — fixed window per client IP, fail-open on Redis problems, shared quota across replicas (see [Rate limiting](#rate-limiting)).
- **OpenTelemetry tracing** (HTTP + Postgres + Redis auto-instrumentation, OTLP HTTP exporter, noop fallback) and **Prometheus metrics** on a private debug port alongside pprof (see [Observability](#observability)).
- **Single-leader cleanup cron** — Postgres advisory locks gate periodic work so exactly one replica per tick performs cleanup (see [Running multiple replicas](#running-multiple-replicas)).
- Layered architecture: handler → service → repository, with interfaces at each boundary.
- Graceful shutdown that drains in-flight requests, flushes traces, and closes infrastructure in order.
- Distroless multistage Docker image (~15 MB) and a turnkey docker-compose stack (see [Docker deployment](#docker-deployment)).
- Health endpoints suitable for Kubernetes liveness/readiness probes.
- Swagger/OpenAPI annotations on all routes (see [Swagger docs](#swagger-docs)).

## Rate limiting

The API installs a Redis-backed fixed-window limiter per client IP, configured via `RateLimitPerMinute` and `RateLimitWindow`. Redis is the shared state so multiple replicas behind a load balancer enforce a single combined quota.

- **Algorithm**: `INCR` on a key shaped like `rl:<ip>:<window_bucket>`, with `EXPIRE` set on the first hit only so the key auto-evaporates.
- **Skipped routes**: `/liveness`, `/readiness`, `/swagger/*` bypass the limiter — health probes shouldn't burn quota.
- **Response on deny**: `429 Too Many Requests`, JSON envelope with `code: "rate_limited"`, headers `X-RateLimit-Remaining: 0` and `Retry-After: <seconds>`.
- **On allow**: `X-RateLimit-Remaining` is set on the response so callers can self-throttle.
- **Fail mode**: fail-open. If Redis is unreachable or a call exceeds `RedisOpTimeout`, the request is allowed and a warning is logged. Availability of the API is preferred over strict rate limiting during a Redis blip.

### Verify it works

```sh
# Burn through the per-minute quota — expect a mix of 2xx and 429.
for i in $(seq 1 $((RateLimitPerMinute=$(grep -E '^RateLimitPerMinute=' .env | cut -d= -f2) + 5))); do
  curl -s -o /dev/null -w "%{http_code}\n" -X POST http://localhost:8080/shorten \
    -H 'Content-Type: application/json' \
    -d '{"url":"https://example.com"}'
done | sort | uniq -c

# Health probe is never throttled.
curl -i http://localhost:8080/liveness
```

To prove the multi-replica behavior: run two API processes on different `ServerPort`s against the same Redis, fire requests at both, and watch the combined count hit `429` at the shared cap.

> **Behind a load balancer / proxy**: configure Gin's trusted proxies (`gin.SetTrustedProxies(...)`) so `c.ClientIP()` reads `X-Forwarded-For` only from the LB. Without it, every request can spoof its rate-limit key.

## Observability

The service emits **distributed traces** via OpenTelemetry and **Prometheus metrics**. Both surfaces are wired in [cmd/api/main.go](cmd/api/main.go) and live in [internal/platform/observability/](internal/platform/observability/).

### Tracing (OpenTelemetry)

Tracing is **off by default**. Set `OtelExporterEndpoint` to enable it; with the env var empty, the SDK installs a no-op `TracerProvider` so `otelpgx`, `redisotel`, and `otelgin` become essentially free.

When enabled:

- **Exporter**: OTLP HTTP — works with the OTel Collector, Jaeger (`:4318`), Tempo, SigNoz, Honeycomb, etc.
- **Propagation**: W3C Trace Context + Baggage. Always installed (even when tracing is off) so context flows across services regardless.
- **Resource attrs**: `service.name=ServiceName`, `service.version=ServiceVersion` plus SDK/process defaults.
- **Sampler**: parent-based with a trace-ID-ratio child. Set `OtelSampleRatio` in [0, 1]; `1.0` samples everything, `0.1` samples 10%.
- **Auto-instrumentation**: inbound HTTP via `otelgin`, Postgres via `otelpgx` ([pool.go](internal/platform/databse/pool.go)), Redis via `redisotel` ([client.go](internal/platform/redisclient/client.go)). One inbound request becomes a single trace covering the limiter check, DB queries, and Redis calls.

### Graceful shutdown

On `SIGINT` / `SIGTERM` the process unwinds in this order, all bounded by `shutdownTimeout` (10s) so a stuck component can't hang the binary:

1. **Stop accepting** — `srv.Shutdown(ctx)` drains in-flight HTTP requests. Their handlers complete, finishing any open spans.
2. **Flush traces** — `tracerShutdown(ctx)` empties the Batch Span Processor queue to the exporter. Doing this _after_ HTTP drain means the last requests' spans still get exported.
3. **Stop debug server** — closes `/debug/pprof/*` and `/metrics`. Scrapers will see one missed scrape, then a clean teardown.
4. **Deferred closes** — `redisClient.Close()` and the DB router cleanup run on `main` returning (LIFO with the `defer`s).

The shutdown context is detached from the root context, so a second `Ctrl+C` doesn't immediately abort the drain — it just cancels the second wait.

### Hardening `:PprofPort` for production

`/debug/pprof/*` and `/metrics` share one listener, so locking down that port locks down both. The current binary listens on `:PprofPort` on all interfaces — fine for a dev box, **not safe for a public host**. Pick one of these for any non-local environment:

- **Bind to localhost only.** Set `PprofPort` to a free port and front it with a sidecar / kubectl port-forward. Today the binary uses `fmt.Sprintf(":%d", cfg.PprofPort)` which binds to all interfaces; if you want a localhost-only build, change that to `127.0.0.1:%d` in [cmd/api/main.go](cmd/api/main.go) — a one-line patch.
- **Kubernetes**: don't put `:PprofPort` in the `Service` that fronts `:ServerPort`. Use a **separate `Service`** label-selected to your Prometheus scrapers (or scrape the Pod directly via a `PodMonitor`/`ServiceMonitor`). For pprof access, prefer `kubectl port-forward pod/<name> 6060:6060` over an ingress rule.
- **Bare-metal / VMs**: a firewall rule that only allows your scrape network (and your operators' jump host) to reach `:PprofPort`. Everything else gets dropped.
- **Never** stick `/metrics` on `:ServerPort`. Per-route latency series and rate-limit counters can leak traffic patterns to anyone who can hit the API.

Health probes (`/liveness`, `/readiness`) live on `:ServerPort` precisely so k8s can keep its probe ACL simple — those don't need a private port.

## Running multiple replicas

The service is designed to scale horizontally. Three independent mechanisms keep multi-replica behavior correct without per-replica configuration:

| Concern | Mechanism | Why it works |
|---|---|---|
| **Rate-limit quota** | Redis fixed-window counters keyed by client IP ([Rate limiting](#rate-limiting)) | All replicas hit the same Redis. The cap holds regardless of replica count. |
| **Cleanup cron** runs once per tick | Postgres advisory lock via [`leader.Locker`](internal/platform/leader/locker.go) | One replica wins `pg_try_advisory_lock`, the rest skip. The lock is session-scoped — if the holder crashes, Postgres releases it on connection close, no stuck-leader. |
| **Metrics** without double-counting | Each replica exposes its own `/metrics`; Prometheus scrapes them as separate targets | The `instance` label distinguishes replicas; aggregations use `sum()` / `rate()` across labels. |
| **Tracing** correlates across replicas | W3C Trace Context propagation (always installed) | Inbound spans inherit `traceparent` from the load balancer or upstream caller, so a single trace covers any replica that handles the request. |

### Verify the rate limiter is shared

Run two API processes against the same Redis (different ports), fire requests at both, and the combined count must hit `429` at the per-IP cap — not `2 × cap`.

```sh
# Terminal A
ServerPort=8080 PprofPort=6060 RateLimitPerMinute=10 go run ./cmd/api

# Terminal B
ServerPort=8081 PprofPort=6061 RateLimitPerMinute=10 go run ./cmd/api

# Terminal C — alternates between the two replicas, total should hit 429 at ~10
for i in $(seq 1 20); do
  port=$([ $((i % 2)) -eq 0 ] && echo 8080 || echo 8081)
  curl -s -o /dev/null -w "%{http_code}\n" \
    -X POST http://localhost:$port/shorten \
    -H 'Content-Type: application/json' \
    -d '{"url":"https://example.com"}'
done | sort | uniq -c
```

### Verify the cleanup cron has a single leader

With two replicas, the cleanup log line should appear from only one of them per tick. Set `LogLevel=debug` to see the per-replica `leader: lock acquired` / `leader: lock held by another process, skipping` lines from [locker.go](internal/platform/leader/locker.go).

### Operational notes

- **Pool sizing** — every replica opens its own DB and Redis pools. Both pools default to 20 max connections; budget your Postgres `max_connections` and Redis `maxclients` for `replicas × 20` plus headroom for migrations.
- **Cleanup interval vs leader lock cost** — the lock costs one round trip to Postgres per tick per replica (the `pg_try_advisory_lock` call), so keep `CleanUpInterval ≥ 30s` if you're running many replicas.
- **Tracing sample ratio** — at scale, drop `OtelSampleRatio` below `1.0`. `0.1` (10%) is a common starting point; the parent-based sampler keeps sampled traces complete across replicas.

## Docker deployment

The repo ships with a **distroless multistage** image and a turnkey compose stack.

### The image

[Dockerfile](Dockerfile) is a two-stage build:

1. **builder** — `golang:1.26.1-alpine`. Downloads modules in a separate layer (so a code-only change keeps the dep cache warm), then compiles a fully static binary with `CGO_ENABLED=0`, `-trimpath`, and `-s -w` to strip symbols. `--mount=type=cache` keeps the module + build cache between builds without bloating the final image.
2. **runtime** — `gcr.io/distroless/static-debian12:nonroot`. ~2 MB base. No shell, no package manager, no glibc. Just CA certs, `tzdata`, the `nonroot` user (UID 65532), and our binary. Because the binary is fully static, the `static` variant is enough — switch to `cc-debian12:nonroot` only if you ever introduce a CGO dependency.

Build args:

```sh
# Local build with a custom tag and version stamp.
docker build \
  --build-arg VERSION=v0.1.0 \
  --build-arg COMMIT=$(git rev-parse --short HEAD) \
  -t url-shortener:v0.1.0 .

# Or use the Makefile (auto-fills COMMIT from git).
make docker-build DOCKER_TAG=v0.1.0
```

The image exposes `8080` (API) and `6060` (debug — pprof + `/metrics`). It runs as `nonroot:nonroot` and has no entrypoint shell — the only command is the binary itself.

### Standalone compose stack

[docker-compose.yml](docker-compose.yml) brings up everything the API needs, in the right order, on one command:

```sh
make compose-up           # or: docker compose up --build -d
```

Services and their roles:

| Service | Image | Role |
|---|---|---|
| `db` | `postgres:16-alpine` | Persistent DB. `pg_isready` healthcheck gates dependent services. |
| `redis` | `redis:7-alpine` | Backs the rate limiter. `PING` healthcheck. Persistence disabled (rate-limit state is ephemeral). |
| `migrate` | `migrate/migrate:v4.18.1` | One-shot migrator. Mounts `./migrations`, runs `up`, exits 0. The api waits on `service_completed_successfully`. |
| `api` | built from `./Dockerfile` | The binary. Healthchecks gate startup so it never sees a half-up DB or unmigrated schema. |

`8080` is published to all interfaces; `6060` is bound to **`127.0.0.1` only** so pprof + `/metrics` aren't reachable from outside the host (see [Hardening :PprofPort for production](#hardening-pprofport-for-production)).

Useful follow-ups:

```sh
make compose-logs         # tail just the api logs
make compose-down         # stop everything (keeps the db-data volume)
docker compose down -v    # also drop the DB volume
```

### Compose stack with observability

Layer [docker-compose.observability.yml](docker-compose.observability.yml) on top to bring up Jaeger + Prometheus and turn tracing on automatically:

```sh
make compose-up-otel
# or: docker compose -f docker-compose.yml -f docker-compose.observability.yml up --build -d
```

You get:

- **Jaeger** UI at <http://localhost:16686> (OTLP HTTP receiver inside the network at `http://jaeger:4318`, set on the api service automatically).
- **Prometheus** UI at <http://localhost:9090>, scraping `api:6060/metrics` per [deploy/prometheus.yml](deploy/prometheus.yml).

Tracing is on automatically — the override sets `OtelExporterEndpoint=http://jaeger:4318` on the api service. To turn it off again, just drop the override file from the command.

```sh
# Smoke test
```

### Producing a release image

The build is reproducible by default (`-trimpath`, no embedded paths). For a tagged release:

```sh
docker build \
  --build-arg VERSION=v1.2.3 \
  --build-arg COMMIT=$(git rev-parse HEAD) \
  -t ghcr.io/your-org/url-shortener:v1.2.3 \
  -t ghcr.io/your-org/url-shortener:latest \

docker push ghcr.io/your-org/url-shortener:v1.2.3
```

For multi-arch images (linux/amd64 + linux/arm64), use `docker buildx build --platform linux/amd64,linux/arm64 ...`. The Dockerfile already honors `TARGETOS` / `TARGETARCH` build args.

## Testing

The suite is split by what each test needs to run.

| Type | Where | Needs |
|---|---|---|
| **Unit (service)** | [internal/service/](internal/service/) — `*_test.go` (not `keygen_test.go`) | nothing |
| **Unit (HTTP middleware)** | [internal/api/middleware/](internal/api/middleware/) — `*_test.go` | nothing |
| **Unit (observability)** | [internal/platform/observability/](internal/platform/observability/) — `*_test.go` | nothing |
| **Unit (rate limiter algorithm)** | [internal/service/ratelimit_service_test.go](internal/service/ratelimit_service_test.go) | nothing — uses `miniredis` in-process |
| **Pure-function / fuzz / bench** | [internal/service/keygen_test.go](internal/service/keygen_test.go) | nothing |
| **Integration (repository)** | [internal/repository/](internal/repository/) — `*_test.go` | Docker daemon running |
| **Integration (leader)** | [internal/platform/leader/locker_test.go](internal/platform/leader/locker_test.go) | Docker (uses real Postgres for advisory locks) |

Unit tests use hand-written fakes (e.g. [fakes_test.go](internal/service/fakes_test.go)) — no DB, no network. The rate-limiter algorithm is exercised against [`miniredis`](https://github.com/alicebob/miniredis) so it stays in the unit bucket; the middleware test uses a fake `RateLimiter` so it never touches Redis at all.

Integration tests use [testcontainers](https://golang.testcontainers.org/) to spin up `postgres:16-alpine`, apply every migration in [migrations/](migrations/) (where applicable), and run each case inside a transaction that auto-rolls-back or against a fresh DB. No `DATABASE_URL` or `.env.test` to manage.

### Quick reference

```sh
# Run everything that doesn't need Docker
make test-unit

# Run everything (unit + integration). Skips integration if Docker isn't running.
make test

# Repo integration suite only — requires Docker
make test-integration

# Benchmarks (default pattern: '.', i.e. all benchmarks)
make test-bench
make test-bench BENCH=ShortKey         # only matching ones
make test-bench BENCH=ShortenURL

# Fuzz a specific target. FUZZ is required; default 30s, override FUZZTIME.
make test-fuzz FUZZ=FuzzShortKeyFromURL
make test-fuzz FUZZ=FuzzShortKeyFromURL FUZZTIME=2m
```

### What each layer asserts

- **Unit tests** ([url_service_test.go](internal/service/url_service_test.go), [cleanup_service_test.go](internal/service/cleanup_service_test.go)): service-layer logic with stubbed repos — collision retries, error wrapping, fire-and-forget logging, context cancellation propagation.
- **Pure-function tests** ([keygen_test.go](internal/service/keygen_test.go)): `shortKeyFromURL` — length, alphabet, determinism. Plus a fuzzer that hammers the function with arbitrary input and a benchmark for regression tracking.
- **Integration tests** ([url_repo_test.go](internal/repository/url_repo_test.go), [request_repo_test.go](internal/repository/request_repo_test.go)): real Postgres via testcontainers — round-trip queries, soft-delete behavior, FK constraints, `ErrNotFound` mapping, and a canary test (`TestPool_DeadlinePropagatesToPostgres`) that proves `pgx` cancellation reaches the server with `pg_sleep`.

### Running a single test or sub-package

```sh
# One test by name
go test -race -run TestShortenURL_HashCollision ./internal/service/...

# One package, verbose
go test -race -v -count=1 ./internal/service/...

# Race detector across the entire suite (the default in our Makefile targets)
go test -race ./...
```

### Fuzz corpus

Failing fuzz inputs are auto-saved under `internal/service/testdata/fuzz/FuzzShortKeyFromURL/`. Commit those — they become regression cases that run as part of the normal `go test`.

### CI considerations

- `make test` is the safe default: it runs unit tests always and integration tests only if Docker is available, so it's a green build on machines or runners without Docker.
- For full coverage in CI, ensure the runner has Docker (most managed CIs do) and call `make test-integration` explicitly.
- `make test-bench` and `make test-fuzz` are not part of the default test run — invoke them separately when you need them.

## Continuous integration

The same five-stage pipeline runs locally (pre-commit hook + `make ci`) and in [GitHub Actions](.github/workflows/ci.yml). All three entry points fail on the same conditions, so a green local run means a green CI run.

| Stage | What it does | Fails when… |
|---|---|---|
| 1. **gofmt** | hook auto-formats staged files; CI checks with `gofmt -l` | CI: any file isn't formatted |
| 2. **go vet** | `go vet ./...` | any vet diagnostic |
| 3. **golangci-lint** | runs with [.golangci.yml](.golangci.yml) (default + `gocritic`, `misspell`, `unconvert`, `unparam`) | any reported issue |
| 4. **build** | `go build ./...` — every package type-checks | compile error |
| 5. **tests + coverage** | `make test-coverage` — full unit + integration suite with `-coverpkg=./...`, then enforces a global coverage floor | total coverage < `COVERAGE_THRESHOLD` (default `60`) |

### Local setup

After cloning, run once:

```sh
make init
```

This installs the version-controlled pre-commit hook ([scripts/git-hooks/pre-commit](scripts/git-hooks/pre-commit)) into `.git/hooks/pre-commit` as a symlink, so updates to the hook are picked up automatically. The target uses `git rev-parse --git-path hooks` so it works inside subdirectory checkouts, worktrees, and submodules.

`golangci-lint` is installed on demand by `make lint` (and therefore by the hook); other tools are installed automatically by their respective targets (`migrate`, `swag`).

### Pre-commit hook

On every `git commit`, the hook runs six stages against the tree as it would land in the commit:

```
→ gofmt              # auto-formats staged .go files and restages
→ swag               # regenerates Swagger docs and restages docs/ when
                     # cmd/api/main.go or any handler is staged. Only runs
                     # when annotation sources are staged; warns and skips
                     # if the swag CLI isn't installed locally.
→ go vet
→ golangci-lint      # warns and skips if not installed locally
→ go build ./...
→ test-coverage      # ≥ 60% required; skipped (with warning) if Docker isn't running
```

Bypass once with `git commit --no-verify`. CI will still enforce on push.

> **Why the swag step is conditional.** Most commits don't touch swag annotations, so the hook silently skips regen — no churn in `docs/` on unrelated commits. When you do touch [cmd/api/main.go](cmd/api/main.go) (the `@title` / `@version` block) or any [handler](internal/api/handlers/) (`@Summary`, `@Router`, `@Param`, ...), the hook regenerates `docs/{docs.go,swagger.json,swagger.yaml}` and **auto-restages them into the same commit**. That keeps the spec in lockstep with the annotations on every push, no manual `make docs` needed.

### Mirror the CI pipeline locally

```sh
make ci
```

Same order as GitHub Actions: gofmt-check → vet → lint → build → test-coverage. Useful right before pushing.

### GitHub Actions

[.github/workflows/ci.yml](.github/workflows/ci.yml) runs two jobs on every push to any branch and every pull request. Concurrency is grouped by ref, so a follow-up push cancels the previous run for the same branch.

| Job | Trigger | What it does |
|---|---|---|
| **`lint + test`** | every push / PR | gofmt-check, vet, golangci-lint, build, `make test-coverage` (≥ `COVERAGE_THRESHOLD`%). Uploads `coverage.out` as an artifact and appends the per-package summary to `$GITHUB_STEP_SUMMARY`. |
| **`docker image`** | every push / PR (build-only); **tag pushes `v*`** also push to GHCR | `needs: lint + test` so it never builds an image whose tests just failed. Uses `docker/build-push-action` with `cache-from/to: type=gha` to keep layer cache warm across runs. |

#### Releasing a tagged image

Tag and push:

```sh
git tag v1.2.3
git push origin v1.2.3
```

CI builds from the tagged commit, logs into `ghcr.io` with the workflow's `GITHUB_TOKEN` (no PAT or extra secret required — `permissions.packages: write` is set on the job), and publishes:

```
ghcr.io/<owner>/<repo>:v1.2.3
ghcr.io/<owner>/<repo>:latest
```

The `VERSION` and `COMMIT` build args are stamped into the binary via `-ldflags` ([Dockerfile](Dockerfile)). Branch / PR builds tag nothing and don't push — they just verify the Dockerfile still works.

> First time only: GHCR packages default to private. After the first successful push, change visibility under the package settings (or set `permissions.packages: write` plus a `org-level` token if you need a different namespace).

### Tuning the coverage gate

```sh
# Lower the floor for a single run (e.g. while ramping up)
COVERAGE_THRESHOLD=40 make test-coverage

# Raise it permanently — edit the default in the Makefile:
#   COVERAGE_THRESHOLD ?= 60
```

When adding tests that move the needle, raise the default in 5-point steps so coverage ratchets forward and never regresses.

## Swagger docs

```sh
go install github.com/swaggo/swag/cmd/swag@latest
go get github.com/swaggo/gin-swagger github.com/swaggo/files
swag init -g cmd/api/main.go -o docs
```

Then expose the UI by adding to [internal/api/router.go](internal/api/router.go):

```go
import (
    _ "github/lakshyakumar/production-ready-url-shortner-server/docs"
    swaggerfiles "github.com/swaggo/files"
    ginSwagger "github.com/swaggo/gin-swagger"

r.GET("/swagger/*any", ginSwagger.WrapHandler(swaggerfiles.Handler))
```

The UI will be available at `http://localhost:8080/swagger/index.html`.
